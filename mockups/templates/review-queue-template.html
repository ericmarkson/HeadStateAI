Screen mockup — Review queue, the Tier-2 batched confirmation surface

A routine backlog, not a gate. 48-hour-rule recurrences and candidate status migrainosus classifications are displayed immediately and queued here for confirmation — they never block capture or recall (tech-spec.md §5.7). This is not the mandatory document gate (FR-3.30, step 7) — that force-surfaces unconfirmed items only when a prior-authorisation packet is requested. This screen is a normal, dismissible, always-accessible list, and the primary user’s gate here is exactly as un-relaxed as anyone else’s.

Demo state

Reviewer-only, chrome world — lets this one mockup show both states side by side; nothing inside the phone frame depicts a control that doesn’t exist in the product (design-system.md §1). The batch-select bar and per-item actions below the notch are real, in-product controls.

Review queue Tier 2 · 48-hour-rule & status migrainosus · batched confirmation
◆ The 48-hour-rule items reuse Timeline’s BoundaryPicker/BoundaryAdjuster verbatim (design-system.md §4, D17/D18) — “Choose a different reading” below opens the same drawer, writing the same override. Confirming a row as-is (singly or via batch) and picking the alternate reading in the drawer are two entry points onto one write, never two competing interactions for the same decision.
◆ Batching only ever accepts the system’s current proposed reading as-is. An item needing the alternate reading or a manual boundary always routes through its own per-item drawer — selecting it for batch confirmation never silently resolves that ambiguity on the item’s behalf (invariant 7). Status migrainosus items are never batch-eligible — ICHD-3 doesn’t decide between it and the ordinary-episode reading, so there is no “current proposed reading” a batch action could honestly accept; each one requires its own explicit confirm/reject.
◆ FR-3.31’s metrics — correction rate, backlog size, timeout rate — are instrumented server-side. This screen intentionally doesn’t render them as UI chrome; it isn’t an analytics dashboard.
